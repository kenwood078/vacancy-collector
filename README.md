# Vacancy Collector

Сбор вакансий с hh.ru, анализ через локальную LLM и подбор вакансий под резюме.
Два источника сбора: cookie-сессия hh.ru и Google Search через Serper.

## Возможности

- Сбор вакансий напрямую с hh.ru или через Serper с файловым кэшем.
- Извлечение стека, задач, сертификатов, доменов и языков через LLM.
- Хранение вакансий, анализа и резюме в PostgreSQL с pgvector.
- Эмбеддинги Qwen3-Embedding-4B и поиск по косинусному расстоянию.
- Фильтрация подбора по опыту, зарплате и городу с учётом готовности к переезду.
- Статистика рынка без LLM и три профильных Markdown-отчёта через CrewAI writer.
- Выбор сетевых инженеров, DevOps/SRE или информационной безопасности при сборе HH.
- Восемь CLI-команд для сбора, анализа, эмбеддингов, резюме и отчётов.

## Требования

- Python 3.10–3.13.
- PostgreSQL 18 с установленным расширением pgvector.
- LM Studio или OpenAI-совместимый сервер с моделями для генерации и эмбеддингов.
- Cookies hh.ru для `collect-hh` и `all-hh`.
- Ключ Serper API для `collect-serper`; HH cookies для этой команды не нужны.

## Настройка

Заполните `.env` по образцу `.env.example`:

- `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` — подключение к БД.
- `HH_TOKEN`, `HH_XSRF` — cookies для прямого сбора.
- `SERPER_API_KEY` — ключ поиска Serper.
- `USE_CACHE`, `CACHE_TTL_HOURS` — кэш Serper; TTL по умолчанию 24 часа,
  нулевое или отрицательное значение отключает истечение.
- `LLM_BASE_URL`, `LLM_API_KEY` — адрес и ключ OpenAI-совместимого сервера.
- `LLM_MODEL` — writer-модель; также используется при сборе через Serper.
- `LLM_MODEL_EXTRACTOR` — модель анализа вакансий и резюме, например `openai/gpt-oss-20b`.
  Если переменная не задана, используется `LLM_MODEL`.
- `EMBEDDING_MODEL` — модель эмбеддингов;
  по умолчанию `text-embedding-qwen3-embedding-4b`, размерность 2560.

Cookies можно взять из DevTools браузера: Application → Cookies → hh.ru.
Значения `hhtoken` и `_xsrf` перенесите в соответствующие переменные `.env`.
Если сессия перестала работать, обновите cookies.

## Команды

| Команда | Назначение | Аргументы |
|---|---|---|
| `collect-hh` | Прямой сбор выбранной специализации | обязательный `--spec`; `--n`, по умолчанию 10 |
| `collect-serper` | Serper → scrape → LLM → БД | `--n`, по умолчанию 10; `--no-cache` |
| `analyze` | Структурированный анализ вакансий без анализа | `--n`; без аргумента — все |
| `embed-vacancies` | Эмбеддинги проанализированных вакансий без вектора | `--n`; без аргумента — все |
| `save-resume` | Чтение, анализ, эмбеддинг и сохранение резюме | обязательный `--path` |
| `match` | Подбор вакансий и Markdown-отчёт | обязательный `--resume-id`; `--top`, по умолчанию 20 |
| `report` | Профильный отчёт через CrewAI writer | обязательный `--spec` |
| `all-hh` | Сбор, затем отчёт той же специализации | обязательный `--spec`; `--n`, по умолчанию 10 |

Полный путь от сбора к подбору:

```bash
python main.py collect-hh --spec network_engineer --n 20
python main.py analyze --n 20
python main.py embed-vacancies --n 20
python main.py save-resume --path data/resume.txt
# Используйте resume_id, выведенный предыдущей командой.
python main.py match --resume-id 6 --top 20
```

`gpt-oss-20b` может обрабатывать одну вакансию около трёх минут.
Для пробного запуска задавайте `analyze --n`; без ограничения обрабатываются
все вакансии без анализа.

Отдельный сбор Serper и профильные отчёты HH:

```bash
python main.py collect-serper --n 20 --no-cache
python main.py report --spec network_engineer
python main.py all-hh --spec devops_sre --n 20
python main.py all-hh --spec security --n 20
```

`all-hh` выполняет сбор и отчёт выбранной специализации;
анализ и эмбеддинги для матчинга запускаются отдельными командами.
Команда `all-serper` удалена: Serper не получает роль HH, необходимую
для профильного отчёта. Его записи без роли сохраняются, но не входят в эти отчёты.

Поддерживаемые форматы резюме: `.txt`, `.md`, `.text` в UTF-8.
Отчёты рынка сохраняются в `outputs/report_<spec>_<timestamp>.md`,
отчёты подбора — в `outputs/match_resume_<id>_<timestamp>.md`.
Отчёт подбора создаётся один раз, включая случай без найденных вакансий.
Каталог `outputs/` создаётся при сохранении отчёта.

## Специализации и отчёты

В `collect-hh`, `all-hh` и `report` аргумент `--spec` обязателен.
Без него или с неизвестным ключом команда завершится с кодом 2 до обращения
к сервисам. Значения по умолчанию нет.

| Ключ | Название | professional_role HH |
|---|---|---:|
| `network_engineer` | Сетевые инженеры и архитекторы | 112 |
| `devops_sre` | DevOps и SRE | 160 |
| `security` | Информационная безопасность | 116 |

Фильтры находятся в `config/specializations.jsonc`. Каждая запись задаёт
`display_name`, `query_hh`, `professional_role`, `area`, `experience`,
`work_format`, `excluded_text`, `search_period`. Ключ — латинские строчные
буквы, цифры и подчёркивания, начиная с буквы. JSONC поддерживает комментарии.
Пути разрешаются относительно проекта, независимо от рабочего каталога.

По умолчанию в самих пресетах: Москва/СПб (`area: [1, 2]`), опыт от года,
REMOTE/HYBRID, последние 30 дней, исключение стажёров, junior и поддержки.
Поиск идёт по названию, зарплата не обязательна.
При редактировании допустимы положительные целочисленные коды роли и регионов,
период 1–30 дней, непустые списки опыта и формата работы из значений HH.
`excluded_text` может быть пустой строкой; остальные строковые поля непустые.
Неверные поля и файлы диагностируются до запуска сбора или отчёта.

Отчёт выбирает **все сохранённые вакансии соответствующей роли HH**,
включая ранее собранные записи. `search_period` ограничивает только новый сбор.
Фильтры пресета не применяются повторно к историческим данным отчёта.
Записи с другой ролью или `NULL` не включаются. Код роли сохраняется из ответа
HH, а не заменяется выбранной специализацией; миграция БД не требуется.
DevOps/SRE ограничен ролью 160: SRE-вакансии с другими ролями HH не входят.

В `config/report_profiles/<spec>.jsonc` находятся:

- `writer`: роль, цель и backstory агента;
- `task`: инструкция и ожидаемый формат отчёта;
- `skills_keywords`: обязательный непустой список терминов для поиска
  в requirements, одинаковый формат для всех трёх профилей; `null` недопустим;
- `skill_groups`: названия профильных групп и списки поисковых терминов.

Сетевой профиль рассматривает вендоров, маршрутизацию/коммутацию, безопасность,
автоматизацию и упоминания сертификатов. DevOps/SRE — CI/CD, контейнеры,
IaC, облака, наблюдаемость и надёжность. Security — SOC/SIEM, защиту
инфраструктуры и конечных устройств, IAM, AppSec, уязвимости и требования.
Общие разделы описывают города, опыт, форматы работы, занятость, зарплаты,
работодателей, навыки и до трёх примеров с URL.

Расчёты используют сырые `requirements` и `key_skills`; `analyze` для отчёта
не требуется. Числа групп считает Python: вакансия учитывается один раз внутри
группы, если найден хотя бы один термин в любом из этих полей. Группы могут
пересекаться; доля считается от общего числа вакансий выбранной роли.
Writer интерпретирует подготовленные данные, не выбирает специализацию
и не получает возможности сменить выборку через аргументы инструмента.
При пустой выборке команда выводит сообщение без запуска LLM и записи отчёта.

Упоминания терминов не являются полной классификацией профессий. Отчёт
не утверждает динамику рынка без сравнения периодов. Настройки CrewAI общие
в `crew.jsonc`, инструменты и настройки writer — в `agents/writer.jsonc`;
его роль, цель и backstory переопределяются выбранным профилем.

Чтобы добавить специализацию, добавьте запись фильтров и одноимённый профиль
отчёта, используя настоящий код роли HH. Укажите ключ явно в `--spec`.
`collect-serper`, анализ, эмбеддинги и matching выбора специализации не имеют;
matching продолжает работать с общей базой проанализированных вакансий.

## Структура и поток данных

```text
main.py                  CLI и запуск CrewAI
src/
├── collectors/          HHClient, SerperClient, scrape, extract_vacancy, pipeline
├── analytics/           VacancyExtractor, ResumeExtractor, stats
├── storage/             VacancyStorage и SearchCache
├── matching/            QwenEmbedder, embedding_text, matcher, match_report, resume_parser
└── tools/               GetStatsTool для writer
config/specializations.jsonc   фильтры HH
config/report_profiles/       writer, инструкции и словари по специализациям
agents/                  общие настройки агентов CrewAI
crew.jsonc               конфигурация CrewAI
tests/                   debug-скрипты для ручных проверок
```

```text
HH search → detail → vacancies
Serper → URLs → scrape → LLM extract → vacancies
vacancies → VacancyExtractor → vacancy_analysis → embed_document
резюме → parse_resume → ResumeExtractor → embed_query → resumes
resumes → SQL-фильтры + векторный поиск → Markdown-отчёт подбора
vacancies WHERE professional_role = роль → GetStatsTool → профиль writer → отчёт рынка
```

Embedding-тексты вакансии и резюме имеют одинаковые подписи и порядок полей.
Инструкция Qwen3 добавляется только к запросу резюме.

## База данных

`VacancyStorage` при создании соединения выполняет `CREATE TABLE IF NOT EXISTS`,
создание расширения `vector` и индексов. База должна существовать,
а пользователь — иметь права на эти операции. Автоматических миграций нет.

| Таблица | Основные поля |
|---|---|
| `vacancies` | `id`, уникальный `url`, `name`, `employer` и его метаданные, `city`, зарплата строкой и числовыми границами, `requirements`, `key_skills`, опыт, формат, занятость, график, роль, даты и число откликов |
| `vacancy_analysis` | `vacancy_id` → `vacancies.id`, структурированные списки, `english_level`, метаданные LLM и анализа, текст и вектор эмбеддинга, модель и дата эмбеддинга |
| `resumes` | `id`, `title`, `role`, `source_text`, город, формат, стаж, зарплатные ожидания и границы, готовность к переезду, структурированные списки, метаданные LLM и эмбеддинга |

В анализе и резюме `stack`, `tasks`, `certifications`, `domains`,
`programming_languages` имеют тип `TEXT[]`. Эмбеддинги — `vector(2560)`.
`vacancies.key_skills` хранит теги hh.ru строкой через запятую.
Точная схема находится в `VacancyStorage._create_table`.
